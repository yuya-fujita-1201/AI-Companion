# Cloudflare Workers プロキシ構築計画
## AI Companionアプリのローカル化戦略

---

## プロジェクト概要

**目的**: AI Companionアプリをサーバーレス・ローカルファーストのアーキテクチャに移行し、App Store/Google Playでの公開とマネタイズを実現する

**現在の課題**:
- Manusサーバーへの依存（Express + tRPC + MySQL + S3）
- ユーザー数増加に伴うサーバーコストの増大
- スケーラビリティの制約

**解決策**: Cloudflare Workersを使用した軽量プロキシ + ローカルストレージ

---

## アーキテクチャの変革

**現在のアーキテクチャ（サーバー依存）**:

モバイルアプリ → tRPC → Manusサーバー → LLM/STT/TTS/S3

**新しいアーキテクチャ（ローカル優先）**:

モバイルアプリ（AsyncStorage + FileSystem） → Cloudflare Workers → OpenAI API

**主要な変更点**:
- すべてのデータをデバイスローカルに保存
- 外部通信はLLM APIのみ（Cloudflare Workers経由）
- バックエンドサーバーを完全削除
- 音声処理はExpo Speech（無料）またはOpenAI API（高品質）

---

## Cloudflare Workersを選んだ理由

**コスト面の優位性**:
- 無料プラン: 100,000リクエスト/日
- 有料プラン: $5/月で1,000万リクエスト
- 従来のVPSと比較して1/10以下のコスト

**パフォーマンス**:
- 世界300以上のエッジロケーションで実行
- ユーザーに最も近いサーバーから応答
- 平均レイテンシ100-500ms

**運用の簡便性**:
- サーバー管理不要
- 自動スケーリング
- デプロイは数秒で完了

**セキュリティ**:
- 環境変数でAPIキーを安全に管理
- Cloudflareの強力なDDoS保護
- アプリにAPIキーを埋め込む必要なし

---

## プロキシの機能設計

**提供するエンドポイント**:

1. **チャットエンドポイント** (`POST /api/chat`)
   - ユーザーメッセージをOpenAI Chat APIに転送
   - AI応答を返す
   - モデル: GPT-4o-mini（コスト効率重視）

2. **音声認識エンドポイント** (`POST /api/transcribe`) - オプション
   - 音声ファイルをOpenAI Whisper APIに転送
   - テキストに変換
   - Expo Speechを使う場合は不要

3. **音声合成エンドポイント** (`POST /api/tts`) - オプション
   - テキストをOpenAI TTS APIに転送
   - 音声ファイルを生成
   - Expo Speechを使う場合は不要

4. **ヘルスチェック** (`GET /health`)
   - サーバーの稼働状況を確認

---

## セキュリティ設計

**APIキーの保護**:
- 環境変数として管理（`wrangler secret`コマンド）
- コードに絶対に含めない
- Gitリポジトリにコミットしない

**CORS対応**:
- 開発環境: すべてのオリジンを許可（`*`）
- 本番環境: 特定のドメインに制限

**リクエストバリデーション**:
- 必須フィールドの存在確認
- 不正なリクエストを早期に拒否
- 適切なエラーメッセージを返す

**エラーハンドリング**:
- すべてのエラーをキャッチ
- 適切なHTTPステータスコードを返す
- ログに詳細情報を記録

**設定ファイル** (`wrangler.toml`):
- Worker名、エントリーポイント、互換性日付
- カスタムドメイン設定（オプション）

## モニタリングと運用

**リアルタイムログ**:
- `wrangler tail`コマンドでログを確認
- リクエスト、レスポンス、エラーをリアルタイム表示

**ダッシュボード分析**:
- リクエスト数（時間別、日別）
- エラー率
- レスポンス時間
- CPU使用量

**アラート設定**:
- リクエスト数が80,000/日を超えた場合
- エラー率が10%を超えた場合
- CPU時間が制限の80%を超えた場合

**ベストプラクティス**:
- 定期的にヘルスチェックを実行
- 使用量を毎日確認
- エラーログを週次でレビュー

## リスクと対策

**リスク1: OpenAI APIのレート制限**
- 対策: モバイルアプリ側でリクエストを制限（1秒に1回まで）
- 対策: 有料プランにアップグレード（60 RPM以上）

**リスク2: Cloudflare Workersの制限超過**
- 対策: 無料プランで100,000リクエスト/日まで対応
- 対策: 超過が予想される場合は有料プラン（$5/月）

**リスク3: デプロイ失敗**
- 対策: ローカルテストを必ず実行
- 対策: ロールバック手順を準備

**リスク4: セキュリティ侵害**
- 対策: APIキーを環境変数で管理
- 対策: CORS設定を本番環境では厳格化
- 対策: レート制限を実装
